# Change Requests Workspace

This folder centralizes change requests (CRs) so the team can review, prioritize, approve, and implement them with full traceability.

## Objective

Provide a single visible location in the repository for:

- New CR submissions
- Delivery status and baseline impact
- Evidence and confirmation logs

## Structure

- `CR-Intake-and-Execution-Plan.md`: Project-manager plan for intake, analysis, approval, and execution.
- `CR-MOTO-002_Compliance_Package_Traceability.md`: Regulatory compliance CR.
- `CR-MOTO-003_MultiCity_Monitoring_Module.md`: Multi-city monitoring CR.
- `CR-MOTO-004_Client_UI_Reorganization.md`: Client UI reorganization CR.
- `Change_Request_Confirmation_Log.md`: Confirmation and publication record for repository updates.

## Team Workflow

1. Create or update a CR markdown file.
2. Classify impact and dependencies.
3. Review in Change Control Board meeting.
4. Update state in the CR file and `CHANGELOG.md`.
5. Publish implementation evidence and baseline result.
